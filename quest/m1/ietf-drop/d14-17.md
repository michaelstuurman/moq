# [S] Bound the request-ID history by design

## Goal

A draft 18+ peer's spent request IDs cost memory bounded by the protocol,
not by a constant whose only effect is closing the session.

## Plan

Drafts 14 to 17 are gone
([moq-dev/moq#6753](https://github.com/moq-dev/moq/pull/6753)), along with
`session::Limits::requests` and the request window it sized. What remains
is the request-ID history, found by the 2026-10-24 pre-cut audit.

`Spent` (`rs/moq-net/src/ietf/control.rs`) keeps every skipped peer request
ID as a run and closes with INTERNAL_ERROR past `HISTORY` (240,000 runs,
matching `@moq/net`), a constant whose only effect is a refusal. Request
streams can arrive out of allocation order
(`requests_reject_reuse_and_wrong_parity` accepts 4, 0, then 2), so a plain
high-water mark that treats lower IDs as spent would close legitimate
sessions.

The choice is between keeping reuse detection, with `Spent`'s memory
bounded by design rather than a refusal constant, or dropping reuse
detection below the high-water mark, argued on behavior: on draft 18+ each
request owns its stream, and the only state keyed by request ID is
`Publisher::joins`, which a reuse confuses only for the reusing peer's own
joining FETCHes. Either choice keeps GOAWAY's cutoff: `Control::goaway`
names the smallest unprocessed ID from the missing runs
(`goaway_freezes_request_admission_at_current_progress` accepts 0 and 4 and
expects 2), so the lowest gap must still be tracked, or a coarser cutoff
argued on behavior, and that regression kept. Mirror the result in
`@moq/net`.
